# Offline Modbus/TCP PCAP Ingestion

OTShield Bench supports deterministic, passive ingestion of sanitized classic-PCAP captures containing Modbus/TCP traffic.

## Supported path

The current bounded implementation supports:

- Classic PCAP files
- Ethernet link-layer frames
- IPv4
- TCP
- Modbus/TCP
- Passive offline parsing only

The adapter does not open sockets, scan devices, transmit packets, inject traffic, or issue industrial control commands.

## Transaction correlation

Modbus/TCP requests and responses are correlated using:

- normalized TCP connection identity; and
- the Modbus transaction identifier.

Each resulting normalized record reports whether the transaction is:

- `matched`
- `unmatched_request`
- `unmatched_response`

## Duplicate and retransmitted traffic

Duplicate packets are identified using endpoint, TCP sequence, and payload information.

Duplicates or retransmissions do not silently create additional independent benchmark transactions. Their count is retained in transaction metadata.

## Provenance

Synthetic test PCAPs generated by the repository are explicitly marked:

`sanitized_fixture`

They must not be interpreted as GRFICS, OpenPLC, plant, production, or real-world capture evidence.

No completed GRFICS/OpenPLC capture experiment is claimed by this implementation.

## Normalized metadata

PCAP-derived records may include:

- Modbus transaction identifier
- protocol identifier
- unit identifier
- request timestamp
- response timestamp
- calculated response latency
- request PDU
- response PDU
- match status
- duplicate count

Telemetry continues to use the versioned `OTB-TELEMETRY/0.1` Event model and the existing `OTB-INGEST/0.1` ingestion model.

## Limitations

This milestone intentionally implements a small deterministic parser rather than a full network-analysis engine.

Current limitations include:

- classic PCAP only;
- Ethernet/IPv4/TCP only;
- no IPv6;
- no PCAP-NG;
- no IP fragment reassembly;
- no general TCP stream reassembly;
- no encrypted protocol decoding;
- no live capture;
- bounded Modbus/TCP decoding.

Future lab-validation work can extend these capabilities while retaining the same provenance and reproducibility requirements.


## Lab-derived provenance

`PcapTelemetryAdapter` defaults to `sanitized_fixture` provenance for repository
fixtures. A separately executed and documented authorized laboratory capture may
instead provide an explicit dataset identifier and `lab_capture` evidence type.

The evidence classification must describe how the PCAP was actually obtained;
changing the provenance fields alone does not convert a fixture into laboratory
evidence.
