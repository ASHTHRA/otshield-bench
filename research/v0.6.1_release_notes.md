## Experimental Results

| Condition | Baseline Recall | Baseline F1 | Robust Recall | Robust F1 |
| --- | ---: | ---: | ---: | ---: |
| clean | 1.0 | 1.0 | 1.0 | 1.0 |
| delay20 | 1.0 | 1.0 | 1.0 | 1.0 |
| delay20_jitter5_loss5 | 0.97 | 0.984561403508772 | 0.97 | 0.984561403508772 |
| delay40_jitter10 | 0.428 | 0.5912675775590125 | 1.0 | 1.0 |
| delay60_jitter10 | 0.0 | 0.0 | 1.0 | 1.0 |

At `delay40_jitter10`, the paired robust-minus-baseline recall difference was
+0.572 with a two-sided 95% interval of approximately
[0.5262050099837566, 0.6177949900162433].

At `delay60_jitter10`, the paired robust-minus-baseline recall and F1
differences were both +1.0 with 95% intervals [1.0, 1.0].

Within this documented laboratory timing setup, the robust detector retained
recall under the heavier tested delay conditions where the fixed baseline did
not. These results do not establish universal detector superiority.

## Resource Measurements

Resource measurements cover detector prediction CPU time, wall-clock time, and
Python `tracemalloc` peak allocations only. They are not measurements of full
deployment cost, host utilization, network infrastructure cost, or total
production-system overhead.

## Scope and Limitations

This release is limited to:

- an isolated OpenPLC laboratory environment;
- read-only Modbus/TCP Function Code 3 experimental validation;
- the documented five network conditions and timing-detector setup.

This release does **not** establish:

- production validation;
- completed independent external replication;
- DNP3 experimental validation;
- EtherNet/IP experimental validation;
- full GRFICS process validation;
- universal detector superiority;
- industry adoption.

The conclusions apply only to the retained experimental evidence and documented
laboratory configuration.
