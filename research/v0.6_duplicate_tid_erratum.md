# v0.6 duplicate-TID execution erratum

## Observed failed run

The real isolated OpenPLC laboratory execution at
`evidence/v06/20260920T203716Z` stopped at `trial-7/clean` with
`ValueError: duplicate transaction 60 in normalized dataset`.
Its protocol specifies 60 transactions, but generic normalization correctly
retained 61 transport records. This is laboratory evidence, not production OT
validation. The failed study remains preserved without modification and will
not be included as the final v0.6 study. A new full study must use a fresh output
directory; its report must disclose this failed attempt rather than pool its
partial results into the final study.

Both TID 60 records in the failed condition are:

| Field | `pcap:0017` | `pcap:0061` |

| Status | unmatched_response | matched |
| Contents | response only | request and response |
| Source endpoint | 192.168.100.2:502 | 192.168.100.3:47088 |

For the matched record, the response reverses the listed endpoints. Both have
protocol ID 0 and unit ID 1. The protocol's TID 60 requests address 9; its
predeclared interval is 100 ms. These schedule fields do not choose the record.

## Root cause

The generic adapter correlates by unordered TCP endpoint pair plus Modbus TID.
The two endpoint pairs differ, so it correctly emits two logical records.
`duplicate_count` counts repeated packets/directions within that correlation key,
not repeated TIDs across connections. The evaluator instead assumed that each
TID occurred only once across the entire capture.

Packet 59 of the clean capture is the orphan response, TCP sequence 2717966168,
acknowledgment 2289058393, payload `003c000000050103020000`. Packet 60 is a client
RST at 1789937214406.115 ms on port 42384. No request on that connection appears
in this capture. The preceding `trial-7/delay60_jitter10/raw.pcap` contains the
same response endpoints, sequence and payload at 1789937205495.958 ms, with
retransmissions at 1789937205761.991 and 1789937206053.736 ms. Its request was at
1789937205495.751 ms, sequence 2289058381. Thus the orphan is a delayed response
retransmission from the preceding condition's connection, not a second clean
transaction. The clean matched request and response are packets 174 and 175;
their TCP sequence numbers are 1072831245 and 4239398143 respectively.

## Deterministic resolution rule

`v06-earlier-foreign-response-only-v1` runs only in v0.6 paired evaluation and
study validation. For a duplicated TID it requires exactly two records: exactly
one matched pair and one response-only record. All captured request-bearing
records must belong to the matched pair's single TCP endpoint pair. The orphan
must use a different connection, the same server endpoint on port 502 and the
same client IP (a different client port). Both must be Modbus/TCP, protocol ID 0,
with identical integer unit IDs. Required PDUs and finite timestamps must exist;
the orphan has neither request timestamp nor request PDU, and its response must
strictly precede the retained request, whose response cannot precede it.

Only this foreign response-only record is excluded from the evaluation view.
All other duplicate configurations fail closed, including two competing matched
transactions, multiple request connections, request-bearing duplicates, missing
transport evidence, or an orphan that follows the retained request. Singleton
unmatched records retain the existing missing-observation behavior. This rule
does not generally prefer matched records over unmatched records.

The original normalized document remains unchanged. Both detectors receive the
same canonical records, with original intervals and latencies: the adapter's
response-only record never advanced the inter-request clock. The result
environment and observations envelope carry additive `canonicalization`
metadata: versioned rule, input/canonical counts, canonical document hash,
zero-based original indices, and full retained/excluded records. The original
normalized hash remains present. Study validation independently recomputes the
view and audit and rejects discrepancies. Old duplicate-free artifacts without
this additive metadata remain readable. Generic ingestion and v0.5 APIs are
unchanged.

## Independence and unchanged protocol

Canonicalization receives only normalized transport records, not the protocol,
expected_anomaly labels as decision inputs, detector output, or performance
metrics. It does not consult telemetry labels, planned intervals, phase names,
response values, or detector thresholds. Synthetic regression tests exercise
reconnect contamination, ambiguity rejection, common paired observations,
provenance validation, and unchanged v0.5 duplicate rejection.

The preregistered protocol file is unchanged. `polling-burst-v1` remains at
50 ms; the frozen historical calibration remains 100.23721899414062 ms, with
its original pinned hash. No calibration or tuning uses the failed study.
The 25-trial, five-condition, 60-transaction design, ground truth, metrics, and
Student-t/paired statistical analysis remain unchanged. This is an explicit
post-failure correction of capture-to-trial correlation, not new detector or
performance evidence. No laboratory study was launched to implement this fix.
